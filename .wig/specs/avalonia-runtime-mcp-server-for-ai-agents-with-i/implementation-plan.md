# Implementation Plan: Avalonia Runtime MCP Server for AI Agents

## Sprint 1: Data Models and JSON Infrastructure

Foundation sprint: create all data models, JSON serialization helpers, and establish the project file structure. No Avalonia dependencies in this sprint — pure C# records and serialization.

- [ ] Create `libs/Six.Avalonia.Mcp/src/JsonOptions.cs` — static class with shared `JsonSerializerOptions` (camelCase, ignore null, compact). Namespace: `Six.Avalonia.Mcp`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/BoundsInfo.cs` — sealed record with `X`, `Y`, `Width`, `Height` (all double, required). Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/AppMetadata.cs` — sealed record with `ProcessName`, `ProcessId`, `MainWindowTitle`, `AvaloniaVersion`, `DotNetVersion`, `WindowCount`, `WindowWidth`, `WindowHeight`. Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/VisualTreeNode.cs` — sealed record with `Type`, `Name`, `Bounds`, `IsVisible`, `IsEnabled`, `Opacity`, `IsFocused`, `IsPointerOver`, `Classes` (IReadOnlyList<string>), `Children` (IReadOnlyList<VisualTreeNode>). Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/FindElementResult.cs` — sealed record with `Type`, `Name`, `Bounds`, `Path` (IReadOnlyList<int>), `ElementId` (string, format "path:0/2/1"). Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/ElementProperties.cs` — sealed record with identity, geometry, state, appearance, layout, data, and style properties as defined in design.md. All appearance values as strings. Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Models/InteractionResult.cs` — sealed record with `Success`, `ErrorMessage`, `ElementType`, `ElementName`, `IsFocused`, `IsEnabled`, `IsVisible`, `IsPointerOver` (nullable bools for post-state). Namespace: `Six.Avalonia.Mcp.Models`.
- [ ] Create unit tests for all models in `tests/Six.Avalonia.Mcp.Tests.Unit/src/Models/` — one test file per model. Test construction, JSON roundtrip serialization via `JsonOptions.Default`, null handling, and camelCase property naming. Use FluentAssertions roundtrip pattern (deserialize and compare, never exact string match). Verify the solution compiles (`dotnet build`) and tests pass (`dotnet test`).

## Sprint 2: Inspector Interface, Element Resolution, and DI Registration

Build the inspector service interface, the DI registration entry point, and internal helper methods for element resolution. This sprint connects the models to Avalonia's visual tree.

- [ ] Create `libs/Six.Avalonia.Mcp/src/Services/IAvaloniaInspector.cs` — interface with all methods as defined in design.md. Methods: `GetAppMetadataAsync`, `GetVisualTreeAsync`, `FindElementAsync`, `GetAncestorChainAsync`, `GetElementPropertiesAsync`, `TakeScreenshotAsync`, `SimulateClickAsync`, `SimulateTypeAsync`, `SetControlStateAsync`, `SimulateHoverAsync`, `SimulateDragAsync`, `SimulateKeyboardShortcutAsync`. All async with CancellationToken. Namespace: `Six.Avalonia.Mcp.Services`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Services/AvaloniaInspector.cs` — class implementing `IAvaloniaInspector`. Constructor takes `ILogger<AvaloniaInspector>`. Add private helper method `GetMainWindow()` that accesses `Application.Current?.ApplicationLifetime` as `IClassicDesktopStyleApplicationLifetime` and returns the `MainWindow`. Log warning if null. All public methods should be async stubs that throw `NotImplementedException` for now (implemented in later sprints).
- [ ] Implement internal helper: `ResolveElement(Visual root, string? name, string? typeName, string? path)` on `AvaloniaInspector`. Walk the visual tree recursively. For `name`: match `Visual.Name`. For `typeName`: match `visual.GetType().Name`. For `path`: split on `/`, navigate by child index. Return null if not found. Mark internal (tested via InternalsVisibleTo).
- [ ] Implement internal helper: `BuildPath(Visual root, Visual target)` — returns `IReadOnlyList<int>` of child indices from root to target. Walk tree with DFS, track indices. Mark internal.
- [ ] Implement internal helper: `GenerateElementId(Visual root, Visual target)` — returns `"path:0/2/1"` string using `BuildPath`. Mark internal.
- [ ] Create `libs/Six.Avalonia.Mcp/src/McpServerHost.cs` — static class with `AddAvaloniaMcpServer(IServiceCollection)` and `AddAvaloniaMcpServer(IHostBuilder)` extension methods. Register `IAvaloniaInspector` as singleton `AvaloniaInspector`. Call `services.AddMcpServer(...)` with server info (name: "Six.Avalonia.Mcp", version from assembly), `.WithStdioServerTransport()`, `.WithToolsFromAssembly()`. Add required usings for `ModelContextProtocol.Server`. Namespace: `Six.Avalonia.Mcp`.
- [ ] Create unit tests for element resolution helpers in `tests/Six.Avalonia.Mcp.Tests.Unit/src/Services/AvaloniaInspectorTests.cs`. Since Avalonia controls can't be easily instantiated in unit tests without a platform, test `ParseKeyCombination` (Sprint 5) and model-level logic. For `ResolveElement`/`BuildPath`/`GenerateElementId`, add tests that document the expected behavior (may need to be integration-level or use Avalonia headless platform). Verify the solution builds and tests pass.

## Sprint 3: Inspection Tools (Visual Tree, Find Element, Properties, Ancestors)

Implement the core inspection tools — the read-only tools that let agents explore the visual tree. This is the most important tool category.

- [ ] Implement `AvaloniaInspector.GetAppMetadataAsync()` — dispatch to UI thread, read process info (`Process.GetCurrentProcess()`), main window title/dimensions from `GetMainWindow()`, Avalonia version from `typeof(Application).Assembly.GetName().Version`, .NET version from `Environment.Version`. Return `AppMetadata` record.
- [ ] Implement internal `BuildTreeNode(Visual visual, int currentDepth, int maxDepth)` on `AvaloniaInspector` — recursive builder. Extract: `Type` = `visual.GetType().Name`, `Name` = `(visual as Control)?.Name`, `Bounds` from `visual.Bounds` (x, y, width, height), `IsVisible`/`IsEnabled` from control properties (default true for non-Control visuals), `Opacity`, `IsFocused` from `(visual as InputElement)?.IsFocused`, `IsPointerOver` from `(visual as InputElement)?.IsPointerOver`, `Classes` from `(visual as StyledElement)?.Classes` (both style classes and pseudo-classes as strings), `Children` recursively (stop at maxDepth). All on UI thread.
- [ ] Implement `AvaloniaInspector.GetVisualTreeAsync(maxDepth, elementName, ct)` — dispatch to UI thread. If `elementName` provided, resolve element first, else use main window. Call `BuildTreeNode`. Return `VisualTreeNode`. Clamp `maxDepth` to range [1, 50].
- [ ] Implement `AvaloniaInspector.FindElementAsync(name, typeName, className, selector, maxResults, ct)` — dispatch to UI thread. Walk tree from main window. For `selector`, implement simple parser: `"Button#myBtn"` = type Button with name myBtn, `"TextBox.error"` = TextBox with class "error", `"#myBtn"` = any type with name myBtn, `".error"` = any type with class error. Return list of `FindElementResult` with path and elementId. Limit to `maxResults`.
- [ ] Implement `AvaloniaInspector.GetAncestorChainAsync(elementName, ct)` — dispatch to UI thread. Find element by name, then walk `VisualParent` chain to root. Return array of `VisualTreeNode` (one per ancestor, no children populated — just identity/bounds).
- [ ] Implement `AvaloniaInspector.GetElementPropertiesAsync(elementName, typeName, path, ct)` — dispatch to UI thread. Resolve element. Extract all properties defined in `ElementProperties` record: read Avalonia dependency properties, convert brushes to `.ToString()`, read margin/padding as comma-separated values, read DataContext type name. Return `ElementProperties`.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Tools/MetadataTools.cs` — `[McpServerToolType]` static class with `[McpServerTool(Name = "get_app_metadata")]` method. Takes `IAvaloniaInspector`, calls `GetAppMetadataAsync`, serializes with `JsonOptions.Default`. Wrap in try/catch returning error JSON on failure.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Tools/InspectionTools.cs` — `[McpServerToolType]` static class with 4 tools: `get_visual_tree`, `find_element`, `get_element_properties`, `get_ancestor_chain`. Each takes `IAvaloniaInspector` + parameters, delegates to inspector, serializes result. All wrapped in try/catch. Verify solution builds. Add unit tests for tool classes in `tests/Six.Avalonia.Mcp.Tests.Unit/src/Tools/InspectionToolsTests.cs` and `MetadataToolsTests.cs` — mock `IAvaloniaInspector`, verify JSON serialization and error handling.

## Sprint 4: Screenshot Tool

Implement the screenshot capture tool using Avalonia's `RenderTargetBitmap`.

- [ ] Implement internal `RenderToBase64Async(Visual visual, double scale)` on `AvaloniaInspector` — dispatch to UI thread. Create `RenderTargetBitmap` with `new RenderTargetBitmap(new PixelSize((int)(bounds.Width * scale), (int)(bounds.Height * scale)), new Vector(96 * scale, 96 * scale))`. Call `renderTarget.Render(visual)`. Save to `MemoryStream` as PNG via `renderTarget.Save(stream)`. Convert to base64. Return tuple `(base64String, pixelWidth, pixelHeight)`.
- [ ] Implement `AvaloniaInspector.TakeScreenshotAsync(elementName, scaleFactor, ct)` — if `elementName` is null, capture main window; else resolve element. Validate `scaleFactor` in [0.5, 3.0]. Call `RenderToBase64Async`. Return `(base64, width, height)` tuple. Handle errors: if visual has zero size, return error.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Tools/ScreenshotTools.cs` — `[McpServerToolType]` static class with `[McpServerTool(Name = "take_screenshot")]` method. Takes `IAvaloniaInspector`, `elementName?`, `scaleFactor?`. Calls `TakeScreenshotAsync`. Returns JSON: `{"base64Png": "...", "width": N, "height": N}`. Try/catch wrapper.
- [ ] Create unit tests in `tests/Six.Avalonia.Mcp.Tests.Unit/src/Tools/ScreenshotToolsTests.cs` — mock inspector returning a known base64 string. Verify JSON structure. Test error cases (element not found). Verify solution builds and tests pass.

## Sprint 5: Basic Interaction Tools (Click, Type, Control State)

Implement the three core interaction tools. These require creating mock pointer infrastructure and understanding Avalonia's event system.

- [ ] Create `libs/Six.Avalonia.Mcp/src/Services/MockPointer.cs` — internal sealed class implementing `Avalonia.Input.IPointer`. Properties: `Id = 0`, `Captured = null`, `Type = PointerType.Mouse`. Methods: `Capture(IInputElement?)` — no-op. This is needed because Avalonia pointer event constructors require an `IPointer` instance. Namespace: `Six.Avalonia.Mcp.Services`.
- [ ] Implement `AvaloniaInspector.SimulateClickAsync(elementName, button, x, y, modifiers, clickCount, ct)` — dispatch to UI thread. Resolve element. Calculate position: if x/y null, use center of element bounds. Map `button` string to `MouseButton` enum. Map `modifiers` string to `KeyModifiers` (parse "ctrl", "shift", "alt"). Create `PointerPointProperties(rawModifiers, PointerUpdateKind.LeftButtonPressed)`. Construct `PointerPressedEventArgs` with positional args per Avalonia 11.3.11 API (source, new MockPointer(), rootVisual, position, timestamp, properties, keyModifiers, clickCount). Call `element.RaiseEvent(pressArgs)`. Then construct `PointerReleasedEventArgs` and call `element.RaiseEvent(releaseArgs)`. Return `InteractionResult` with post-state.
- [ ] Implement `AvaloniaInspector.SimulateTypeAsync(elementName, text, ct)` — dispatch to UI thread. Resolve element. Focus it first via `(element as InputElement)?.Focus()`. For each char in text: if printable, raise `TextInputEvent` with the char. If special key (detect `\b` for Backspace, `\n` for Enter, `\t` for Tab), raise `KeyDown`/`KeyUp` with the corresponding `Key` enum value. Return `InteractionResult` with post-state.
- [ ] Implement `AvaloniaInspector.SetControlStateAsync(elementName, stateType, value, ct)` — dispatch to UI thread. Resolve element. Parse `stateType`: `"focus"` → call `Focus()` or blur, `"enabled"` → set `IsEnabled`, `"visible"` → set `IsVisible`. Return `InteractionResult` with new state values.
- [ ] Implement internal `ParseKeyCombination(string keys)` on `AvaloniaInspector` — parse key combo strings like `"Ctrl+S"`, `"Ctrl+Shift+Z"`, `"Alt+F4"`. Split on `+`, identify modifiers (Ctrl/Shift/Alt/Meta), remaining part is primary key parsed via `Enum.TryParse<Key>`. Return `(KeyModifiers, Key)` tuple. Mark internal.
- [ ] Create `libs/Six.Avalonia.Mcp/src/Tools/InteractionTools.cs` — `[McpServerToolType]` static class with 3 initial tools: `simulate_click`, `simulate_type`, `set_control_state`. Each takes `IAvaloniaInspector` + parameters, delegates to inspector, serializes result. Try/catch wrapper.
- [ ] Create unit tests: `tests/Six.Avalonia.Mcp.Tests.Unit/src/Tools/InteractionToolsTests.cs` — mock inspector, verify delegation and JSON output for click/type/state tools. Also test `ParseKeyCombination` directly (internal access). Test edge cases: unknown button name, empty text, invalid state type. Verify solution builds and tests pass.

## Sprint 6: Advanced Interaction Tools (Hover, Drag, Keyboard Shortcuts)

Implement the remaining three interaction tools.

- [ ] Implement `AvaloniaInspector.SimulateHoverAsync(elementName, exitAfter, ct)` — dispatch to UI thread. Resolve element. Construct `PointerEventArgs` with `PointerEntered` routed event (source, MockPointer, rootVisual, center position, timestamp, properties, modifiers). Call `element.RaiseEvent(enterArgs)`. Then construct `PointerMoved` event and raise it. If `exitAfter` is true, construct and raise `PointerExited` event. Return `InteractionResult`.
- [ ] Implement `AvaloniaInspector.SimulateDragAsync(elementName, startX, startY, endX, endY, button, steps, ct)` — dispatch to UI thread. Resolve element. Create `PointerPressedEventArgs` at (startX, startY) and raise. Then generate `steps` intermediate points linearly interpolated from start to end, raise `PointerMoved` for each. Finally raise `PointerReleasedEventArgs` at (endX, endY). Return `InteractionResult`.
- [ ] Implement `AvaloniaInspector.SimulateKeyboardShortcutAsync(keys, elementName, ct)` — dispatch to UI thread. If `elementName` provided, resolve and focus it; else use currently focused element or main window. Call `ParseKeyCombination(keys)`. Raise `KeyDown` with modifiers + primary key. Then raise `KeyUp` for primary key and modifiers. Return `InteractionResult`.
- [ ] Add `simulate_hover`, `simulate_drag`, `simulate_keyboard_shortcut` tools to `InteractionTools.cs` — 3 new `[McpServerTool]` methods delegating to the inspector. Wrap in try/catch.
- [ ] Create/extend unit tests in `InteractionToolsTests.cs` — test hover, drag, and keyboard shortcut tool methods with mocked inspector. Test `ParseKeyCombination` edge cases: single key ("F5"), modifier-only ("Ctrl"), triple modifier ("Ctrl+Shift+Alt+S"), case insensitivity. Verify solution builds and all tests pass.
